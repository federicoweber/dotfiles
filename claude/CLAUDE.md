# Instructions

## Linear Issues

- When starting work on a Linear issue, first check out the latest main branch (`git checkout master && git pull`), then create a new branch using the Linear branch name on top of it. Also mark the issue as in progress in Linear

## Commits

- Commit frequently while working on tasks — after each meaningful change or logical step, not just at the end
- Use clear, concise commit messages that describe what changed and why

## Pull Requests

- Do not add a "Test plan" section in PR descriptions by default
